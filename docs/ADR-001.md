# ADR-001 — Core condiviso, local-first (proposta implementata in parte)
Stato: proposta per PR, 2026-11-24. Master plan ID 01–02, R02/R10/R13/R14.

## Decisione
Separare acquisizione (documenti non attendibili), normalizzazione (Building Core), regole catastali deterministiche versionate, geometria, classamento e adattatori ufficiali. UI non decide regole; AI propone intenti e cita evidenze, non assegna identificativi ufficiali. Il Core è un contratto JSON indipendente dal linguaggio, non un servizio cloud obbligatorio. Prima implementazione di validazione in ECMAScript senza dipendenze; motori Python/Rust futuri potranno consumare il contratto. Desktop Windows prioritario per interazione con DOCFA ufficiale; nessun formato proprietario ricostruito senza verifica.
 
## Confini e dati
- Workspace locale cifrabile tramite sistema operativo; chiavi in keystore, niente chiavi nel repository. Cifratura, persistenza e cancellazione sono requisiti futuri, non implementati.
- OCR/PDF/DXF e output AI sono input non attendibili, mai istruzioni eseguibili. Parser isolati con limiti di risorse; nessun accesso a rete o file arbitrari da contenuto importato.
- Identificativi applicativi opachi, separati da riferimenti catastali. Un'unità può avere più riferimenti; dati mancanti sono null con stato unknown, non inventati. Il contratto distingue osservato, calcolato e proposto; non equivale a verifica ufficiale.
- Fonte = riferimento locale opaco, tipo e data, non file, indirizzo, nome o testo libero. Originali e metadati sensibili restano nello studio. Anche il JSON con identificativi catastali reali è riservato; non pubblicarlo.
- Pianta Libera fornisce geometria con scala e coordinate documentate (estensione futura); MPE gestisce titoli edilizi; APE Italia gestisce dati energetici. I tre giudizi non sono equivalenti. Ogni adattatore usa lista di campi consentiti e consenso esplicito al trasferimento; nessun invio automatico a modelli esterni.
- Firma e invio SISTER restano operazioni esplicite del professionista. Stati trasmesso, protocollato e registrato sono distinti; nessuna registrazione dedotta da sola trasmissione.
 
## Threat model iniziale
| Rischio | Contromisura progettata | Evidenza attuale |
|---|---|---|
| Dati reali in Git pubblico | fixture sintetiche, ignore workspace, revisione diff | fixture sintetiche; ignore non è una barriera assoluta |
| Input manipolato o prompt injection | schema chiuso, parsing separato, nessuna azione automatica | validazione struttura; sandbox futura |
| Collisioni o perdita di graffature | array di riferimenti per unità, chiavi uniche nel documento | test di struttura e riferimenti |
| Falsa attestazione di conformità | stati delle evidenze, domini separati, gate professionale | nessun campo di attestazione nel core iniziale |
| Alterazione PDF telematico | adattatore ufficiale, hash e file immutabile | futuro |
| Dipendenze compromesse | core senza dipendenze, CI con permessi minimi, action pin | CI da verificare |
| Dati eccessivi verso altri progetti | allowlist per adattatore, local-first, consenso | futuro |
 
## Revisione del piano (sequenziale)
Rilievi incorporati: non trattare un graffato come più unità; distinguere assenza documentata di sezione/sub da identificativo ignoto; non confondere provenienza dichiarata con autenticità; schema chiuso e versionato prima di scambiare dati. Nessuna regola catastale o integrazione reale in questa PR. Evoluzioni incompatibili richiedono nuova versione e migrazione esplicita.
