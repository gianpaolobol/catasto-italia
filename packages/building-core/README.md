# Building Core v0.1.0 (draft)
Contratto JSON locale, iniziale, indipendente dai motori e non equivalente a una visura. Usa stringhe opache per gli identificativi; i valori null di section/subaltern significano assenza documentata, non dato parziale. Un riferimento incompleto deve restare unknown con value null in questa versione; i dati parziali rimangono nell'acquisizione originale. Una unità può contenere più riferimenti. Lo stato observed indica provenienza dichiarata, non autenticità certificata. La data asOf è la data di riferimento dichiarata; capturedOn è la data di acquisizione della fonte. Il validatore controlla la struttura, la validità calendariale, la presenza delle fonti e collisioni testuali esatte tra riferimenti observed (non normalizzazione ufficiale). Le proposte non equivalgono a disponibilità ufficiale. Non vi sono ancora geometria, diritti, classamento, import o adattatori. Le regole semantiche supplementari sono in index.mjs; un consumatore del solo JSON Schema non le applica automaticamente. Il JSON contenente identificativi reali è riservato.

Esecuzione test: `node --test tests/building-core.test.mjs` (Node 22 consigliato). Nessuna dipendenza esterna.

Limiti tecnici v0.1.0 (non limiti catastali): 10.000 unità/fonti per snapshot, 1.024 riferimenti per unità, 256 collegamenti fonte per asserzione e 200.000 visite al validatore. Superato un limite il documento non è valido per il Core; non è un giudizio di conformità catastale. Il chiamante dovrà inoltre imporre limiti alla dimensione del file prima del parsing JSON; tale ingestione non è inclusa qui.
